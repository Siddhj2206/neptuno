# User Config Defaults — `/etc/skel` root

Everything in this directory is rsynced **directly to `/etc/skel`** during the
build (`build/10-build.sh`), so a freshly created user gets these as their
initial dotfiles. It is the home for *user-level* config of anything the image
ships.

## Layout (dotfiles live at the tree root, mirroring `~`)

```
custom/config/
└── .config/
    ├── niri/
    │   ├── config.kdl          # copied from DMS docs (compositors.mdx, niri)
    │   └── dms/                # stubs: colors/layout/alttab/binds.kdl
    │                           #   (MANAGED by DMS — regenerated on run/setup;
    │                           #    must exist or niri errors on startup)
    ├── ghostty/
    │   ├── config              # copied from DMS embedded defaults
    │   └── themes/dankcolors   # theme file, regenerated by matugen
    └── DankMaterialShell/      # NOT seeded — DMS auto-generates settings.json
```

## Rules

- Only **user-level** config goes here. System-level config (greetd
  `config.toml`, systemd units/presets, zram) belongs in `build/*.sh` or
  `custom/systemd/` — not here.
- Keep the tree a faithful mirror of `~`: use `.config/…` paths, never
  absolute paths.
- Files land in `/etc/skel` — new users get them; existing users are NOT
  overwritten (their `~` wins).

# User Config Defaults — `/etc/skel` root

Everything in this directory is rsynced **directly to `/etc/skel`** during the
build (`build/10-build.sh`), so a freshly created user gets these as their
initial dotfiles. It is the home for *user-level* config of anything the image
ships.

## Layout (dotfiles live at the tree root, mirroring `~`)

```
custom/config/
└── .config/
    ├── niri/
    │   ├── config.kdl          # hand-maintained copy of the DMS niri template
    │   └── dms/                # working copies of the DMS niri fragments:
    │                           #   binds, windowrules, layout, colors, input,
    │                           #   alttab, wpblur
    │                           #   DMS does NOT reliably regenerate them
    │                           #   (binds in particular), so these ARE the
    │                           #   keybind/window-rule defaults new users get
    ├── ghostty/
    │   ├── config              # copied from DMS embedded defaults
    │   └── themes/dankcolors   # theme file, regenerated by matugen
    └── DankMaterialShell/      # NOT seeded — DMS app settings (settings.json)
```

## Rules

- `niri/dms/*.kdl` are DMS's own output format ("DO NOT EDIT" headers), but the
  shipped copies are the source of truth for a new user's binds and window
  rules. Change them in DMS Settings on a running system, then re-copy
  `~/.config/niri/dms/*.kdl` into this tree — never hand-edit them here, or the
  next copy round will silently revert your edit.
- `dms/wpblur.kdl` ships for parity but is not included by `config.kdl`; add
  `include optional=true "dms/wpblur.kdl"` there if the wallpaper backdrop blur
  should be active.
- DMS app settings (`settings.json`) are deliberately not seeded: they are
  per-user state, not defaults.

- Only **user-level** config goes here. System-level config (greetd
  `config.toml`, systemd units, zram) belongs in `build/*.sh` or
  `custom/systemd/` — not here.
- Keep the tree a faithful mirror of `~`: use `.config/…` paths, never
  absolute paths.
- Files land in `/etc/skel` — new users get them; existing users are NOT
  overwritten (their `~` wins). To copy the Niri, Ghostty, and DMS defaults to
  an existing user, explicitly run `ujust install-dms-config`; image updates
  and logins never apply them automatically.

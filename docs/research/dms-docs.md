## 2. Config system

### 2.1 Main config directory & files (exact names)

User-space DMS data lives in three XDG dirs (**cleanup/reference paths**, from `managing.mdx:323`):

```
~/.config/DankMaterialShell/          # settings.json, plugins.lock.json, cheatsheets/
~/.local/state/DankMaterialShell/     # session.json, plugins/{id}_state.json
~/.cache/DankMaterialShell/           # cache
~/.cache/quickshell/dankshell/        # dms-colors.json (matugen color scheme output)
```

**`~/.config/DankMaterialShell/settings.json`** — the main JSON config (manual edits documented):
- Shadow/elevation keys — `advanced-configuration.mdx` ("If you manually edit `settings.json`, use: `~/.config/DankMaterialShell/settings.json`")
- Custom theme selection: `{"currentThemeName": "custom", "customThemeFile": "/path/to/mytheme.json"}` — `custom-themes.mdx:183-192`
- IMAGE_format is JSON **only**. No kdl fragments are read by DMS itself; the `.kdl` files under `~/.config/niri/dms/` are **niri config fragments that DMS writes**, not DMS config files.

Other generated/synced files:
- `~/.config/DankMaterialShell/plugins.lock.json` — plugin lockfile, **kept in sync by DMS** with managed plugin installs + exact Git commits (README.md:104-106).
- `~/.local/state/DankMaterialShell/session.json` — live session/wallpaper state (symlinked into greeter cache).
- `~/.cache/quickshell/dankshell/dms-colors.json` — the DMS color scheme generated by matugen (manual greeter sync symlinks this to `/var/cache/dms-greeter/colors.json`, `dankgreeter/configuration.mdx` — "Manual Sync").
- `~/.config/matugen/config.toml` — user-supplied custom matugen templates section `[config]` (`application-themes.mdx:39-51`).
- `~/.config/environment.d/90-dms.conf` — environment file (systemd) created by installer; used for `TERMINAL`, Qt theme vars, `DMS_*` overrides (`advanced-configuration.mdx` "Systemd / DankInstall Users").

### 2.2 Auto-generation — what DMS creates vs what the user must create

**Auto-generated by DMS itself:**
- `~/.config/DankMaterialShell/settings.json` **regenerates defaults if deleted** — `managing.mdx:333-335` (Troubleshooting): *"Settings not applying: Backup and remove `~/.config/DankMaterialShell/settings.json` … Restart DMS to regenerate defaults."* This is the canonical auto-generation statement.
- `~/.local/state/DankMaterialShell/session.json` — live session state managed by DMS.
- `~/.config/DankMaterialShell/plugins.lock.json` — written by DMS (README.md:104-106).
- `~/.cache/quickshell/dankshell/dms-colors.json` + themed app outputs (`~/.config/gtk-3.0/dank-colors.css`, `gtk-4.0/dank-colors.css`, `qt5ct/colors/matugen.conf`, `qt6ct/colors/matugen.conf`, `qtengine/config.json`) — generated when matugen is enabled, on wallpaper changes/theme switches (`application-themes.mdx:126-132`).

**NOT auto-created — the user must create/include (big one for pluto's niri config):**
- The niri fragment files `~/.config/niri/dms/{colors,layout,alttab,binds}.kdl` are **not** created by simply running `dms`. Docs explicitly tell the user to create them, and the include must only be added once they exist:
  - `compositors.mdx:38-44`: "Be sure that all files exist before including them in the niri configuration. `mkdir -p ~/.config/niri/dms; touch ~/.config/niri/dms/{colors,layout,alttab,binds}.kdl`"
  - `nixos-flake.mdx` (Config includes): "The files referenced by `filesToInclude` must exist or niri will error on startup. If you're not generating them through home-manager, use `dms setup` to deploy the defaults."
  - They ARE generated on demand by **`dms setup`** (and its per-file subcommands `binds/colors/layout/outputs/cursor/windowrules/alttab` — `cli-setup.mdx`), or individually by the Settings UI "First Time Setup" banner (creates the managed `windowrules.kdl` fragment + adds the include — `compositors.mdx:194-196`).

### 2.3 The `dms/{colors,layout,alttab,binds}.kdl` fragment mechanism (niri)

`compositors.mdx:27,30-36` — "DMS will automatically apply key binds, gaps, window radius, and colors if you include the following files in your niri config. You can customize gaps, border radius, and window radius in **Settings → Compositor**."

```kdl
// Add to the end of ~/.config/niri/config.kdl
include "dms/colors.kdl"
include "dms/layout.kdl"
include "dms/alttab.kdl"
include "dms/binds.kdl"
```

- File layout: `~/.config/niri/dms/*.kdl` (relative include resolves against `~/.config/niri/`).
- There is also a managed `~/.config/niri/dms/windowrules.kdl` for DMS's "Open Windows Floating" rule (`compositors.mdx:194-196`); a First Time Setup banner creates it and adds the include. DMS windows use app-id `com.danklinux.dms` — remove hand-written rules targeting old `org.quickshell` id.
- `dms setup` subcommands write to exactly these paths (`cli-setup.mdx` table): `binds → ~/.config/niri/dms/binds.kdl`, `colors.kdl`, `layout.kdl`, `outputs.kdl`, `cursor.kdl`, `windowrules.kdl`, and `alttab.kdl` (niri only). Setup skips files that already have content. Options are mirror-generated for Hyprland as `.conf`/`.lua` includes (`require("dms.colors")` etc., `compositors.mdx:206-219`).
- niri startup is `spawn-at-startup "dms" "run"` (if not using systemd) — `compositors.mdx:86`.
- Recommended niri layout: transparent background (`layout { gaps 5; background-color "transparent" }`) and layer rules placing the *quickshell* wallpaper layer behind the overview: `layer-rule { match namespace="^quickshell$" place-within-backdrop true }`, plus optionally `namespace="dms:blurwallpaper"` when Blur Layer is on (`compositors.mdx:50-75`). Full component namespace list in `layers.mdx` (all `dms:*`; bar `dms:bar`, modals e.g. `dms:clipboard`/`dms:spotlight`/`dms:settings`, popouts `dms:popout`, etc.).

### 2.4 The `colors` (matugen) flow

- DMS uses **matugen** to generate Material-3 color schemes from the wallpaper, extended with its own **dank16** palette (`cli-doctor.mdx` "matugen": "DMS leverages matugen with custom color enrichment (dank16) to generate themes for itself and various applications, terminals, and IDEs").
- Theme files map 1:1 to matugen color keywords (`.json`, separate `dark`/`light` variants), `matugen_type` selects the scheme algorithm (`scheme-tonal-spot` default; also content/expressive/fidelity/fruit-salad/monochrome/neutral/rainbow/smart) — `custom-themes.mdx:25,154` + repo `docs/CUSTOM_THEMES.md`.
- On wallpaper change/theme switch, DMS regenerates themed app colors: GTK3/4 `dank-colors.css`, qt5ct/qt6ct `matugen.conf`, `qtengine/config.json`, terminals (kitty/alacritty/ghostty/foot/wezterm, `.default` variants for "Always use Dark") — `application-themes.mdx:21,124-134`.
- GTK3 dynamic theming uses **adw-gtk3**: DMS copies it into `~/.local/share/themes` and patches copies with generated colors; without it, falls back to a global `dank-colors.css` import (`cli-doctor.mdx` "adw-gtk3"). Fedora package: `adw-gtk3-theme`.
- `DMS_DISABLE_MATUGEN=1` disables dynamic theming (`advanced-configuration.mdx`).

### 2.5 Env vars (DMS_*) — advanced-configuration.mdx
`DMS_SOCKET`, `DMS_DISABLE_MATUGEN`, `DMS_ENABLE_GTK_REFRESH`, `DMS_DISABLE_CAVA`, `DMS_DISABLE_LAYER`, `DMS_DANKBAR_LAYER`/`DMS_POPOUT_LAYER`/`DMS_MODAL_LAYER`/`DMS_OSD_LAYER` (default overlay)/`DMS_NOTIFICATION_LAYER`, `DMS_DISABLE_POLKIT`, `DMS_PREFERRED_BATTERY`, `DMS_HIDE_TRAYIDS`, `DMS_FORCE_EXTWS`, `DMS_IPP_HOST/PORT/USERNAME/PASSWORD`, `DMS_SCREENSHOT_EDITOR` (swappy/satty). Set in niri via `environment { ... }` block; via systemd in `~/.config/environment.d/90-dms.conf`.

## 3. CLI: `dms`, `dms-cli`, `dms-greeter` — documented commands

**There is no separate `dms-cli` command.** "dms-cli" appears only as a package name in the DankLinux packaging note (`danklinux/index.mdx:409` lists `dms`, `dms-cli`, … as official packages) and as the generic label for the backend CLI ("DMS CLI is the backend and command-line interface for DMS", `cli-doctor.mdx:60`). The actual CLI binary is **`dms`** (Go backend; the Quickshell UI is embedded; separate `dankinstall` handles interactive install). `dms-greeter` is a separate single-binary from `AvengeMedia/dank-greeter`.

## 4. greetd integration (as documented)

### Manual greetd config — `dankgreeter/installation.mdx` "Manual Setup"
`/etc/greetd/config.toml`:
```toml
[terminal]
vt = 1

[default_session]
user = "greeter"
command = "dms-greeter --command niri"
```
Other compositors: `--command Hyprland` / `sway` / `miracle-wm`. Then `sudo systemctl disable gdm lightdm sddm`, `sudo systemctl enable greetd && sudo systemctl start greetd`.

### Custom compositor config for the greeter (`-C` flag) — `dankgreeter/configuration.mdx`
For **niri**, baseline at `/etc/greetd/niri.kdl`:
```kdl
hotkey-overlay {
    skip-at-startup
}
environment {
    DMS_RUN_GREETER "1"
}
gestures {
  hot-corners {
    off
  }
}
layout {
  background-color "#000000"
}
```
then `command = "dms-greeter --command niri -C /etc/greetd/niri.kdl"`. (Analogous baselines: `/etc/greetd/hypr.lua`, `/etc/greetd/sway`, `/etc/greetd/mango.conf`, `/etc/greetd/miracle-wm.yaml`, all with `DMS_RUN_GREETER "1"`.)

### greeter user & cache (systemd declarations — CRITICAL for bootc/atomic)
`dankgreeter/installation.mdx` "Greeter system user":
- `/usr/lib/sysusers.d/dms-greeter.conf` — declares `greeter` UNIX account (home `/var/lib/greeter`, shell `/bin/bash`)
- `/usr/lib/tmpfiles.d/dms-greeter.conf` — creates `/var/cache/dms-greeter` and `/var/lib/greeter` owned `greeter:greeter`
- "…the `greeter` user is recreated from `/usr` on every boot. That matters on **Fedora Atomic, Universal Blue, bootc, and other ostree systems** where install-time `useradd` in `/etc/passwd` may not persist."

### Greeter runtime config (what it reads)
Three read-only files under `/var/cache/dms-greeter/` (override `DMS_GREET_CFG_DIR`; NixOS: `/var/lib/dms-greeter/`):
- `settings.json` — appearance/behavior (theme, clock, weather, fonts; full JSON schema documented)
- `session.json` — wallpaper config (`wallpaperPath`, `wallpaperFillMode`, per-monitor `monitorWallpapers`)
- `colors.json` — color scheme (same format as DMS custom themes)
Multi-user per-account slots under `/var/cache/dms-greeter/users/<username>/` (symlinks to live DMS state: `settings.json`→`~/.config/DankMaterialShell/settings.json`, `session.json`→`~/.local/state/DankMaterialShell/session.json`, `colors.json`→DMS scheme, plus `greeter_wallpaper_override.jpg` copy; profile photo read from `~/.face`/`~/.face.icon`/AccountsService).

### PAM
- Greeter follows `/etc/pam.d/greetd`; DMS can manage its fingerprint/security-key entries, or **Use system PAM authentication** makes it stop writing the file (`dankgreeter/authentication.mdx`).
- Lock screen PAM is **separate** (DMS-managed vs system PAM; `dms auth` CLI; OR/AND factor modes) — `lock-screen-authentication.mdx`.
- Fedora fingerprint: `sudo dnf install fprintd fprintd-pam; fprintd-enroll`.

## 5. What DMS owns / replaces — do-not-configure-separately list (for pluto's niri config)

**DMS is a full DE-equivalent shell** (overview.mdx; README.md:22): "It replaces waybar, swaylock, swayidle, mako, fuzzel, polkit, and everything else you'd normally stitch together to make a desktop."

Blog v1 release note is the most explicit do-not-stitch list (`blog/2025-12-10-v1-release/index.mdx:335`): *"DMS replaces many tools commonly used for Wayland desktops. No `brightnessctl`, `ddcutil`, `grimblast`, `nmcli`, `iwctl`, `grim`, `slurp`, `wofi`, `fuzzel`, `swayidle`, `hyprlock`, `mate/gnome/kde polkit`, `mako/dunst`, `hyprpicker`, `sddm`, or (a bunch of other stuff) needed anymore."*

**Do NOT separately configure in niri/pluto (DMS provides):**
- **Bar/panel** (DankBar), **dock**, **desktop widgets**, **launcher/Spotlight**, **file/web/emoji/calc search** (uses optional `dsearch`)
- **Notifications** (center + popups, DnD) — replaces mako/dunst
- **Lock screen** (session-lock protocol) — replaces swaylock/hyprlock; idle **auto-lock/suspend** (AC vs battery), **IdleMonitor/IdleInhibitor** — replaces swayidle
- **Polkit agent** (native; disable only via `DMS_DISABLE_POLKIT` if you bring your own)
- **Network**, **VPN**, **Bluetooth**, **Audio/PipeWire** management, **brightness** (backlight/i2c/ddc), **power profiles**, **night mode/gamma**, **clipboard history** (replaces cliphist daemon — v1.2 migration removes existing clipboard daemon), **screenshots** (swappy default / satty), **system tray**, **MPRIS/media + audio visualization**, **system sounds**, **system updater widget**, **printer (IPP/CUPS) mgmt**, **browser picker + `dms open` URL handler**, **khal calendar enrichment**, **boost via optional `dgop`** (process/system monitoring).
- **greeter/display manager:** `dms-greeter` replaces the DM (enabling it "will replace your current display manager").

**niri config should only** include the `dms/*.kdl` fragments, spawn `dms run` (or systemd), set env vars, add layer rules for the wallpaper namespace(s), and optionally hand-written window rules (DMS can manage the floating rule itself via `windowrules.kdl`).

## 6. Known gotchas / warnings (from the docs)

1. **Include fragments must pre-exist or niri won't start** — `compositors.mdx:38-44`, `nixos-flake.mdx`: files referenced by `filesToInclude` must exist or **niri errors on startup**; deploy via `dms setup` or `touch` the files before adding the includes.
2. **Don't run DMS twice** — with systemd enabled, remove `spawn "dms" "run"` / `exec-once=dms run` from compositor config (`installation.mdx:717-721`, `managing.mdx:60-64`). Troubleshoot with `dms kill && dms restart`.
3. **Systemd session binding** — `systemctl --user enable dms` starts DMS in *all* DEs; on niri use `systemctl --user add-wants niri.service dms` so it runs only under niri (`installation.mdx:727-741`).
4. **Quickshell version mismatches** — "Older versions of quickshell may result in a reduced feature set"; `undefined symbol` error naming `Qt_6_PRIVATE_API` = quickshell built against different Qt libs → rebuild; full features (Polkit, IdleMonitor, IdleInhibitor, ShortcutInhibitor) currently require **`quickshell-git` or quickshell from the DankLinux repos** (`cli-doctor.mdx:64-79,132-135`). DMS CLI version should match shell version.
5. **Wayland env vars** — `QT_QPA_PLATFORM=wayland`, `QT_QPA_PLATFORMTHEME=gtk3` (+ `QT6`), `ELECTRON_OZONE_PLATFORM_HINT=auto`, `XDG_CURRENT_DESKTOP`; set via niri `environment {}`, `~/.config/environment.d/90-dms.conf` (systemd), or `systemctl --user edit dms`. Niri snippet in `compositors.mdx:94-102`. `environment.d` changes need logout/login (`managing.mdx:207`).
6. **TTY / non-systemd startup** — D-Bus session bus (`dbus-run-session niri`) + `XDG_RUNTIME_DIR` fallback + seat manager (elogind, not both elogind+seatd) — `installation.mdx:543-582`; but "If you use `dms-greeter`, all seat management, D-Bus initialization, and runtime directories are handled for you automatically."
7. **Immutable/image systems (bootc!)** — `dms-greeter install/enable/uninstall` are **disabled by CLI policy** on Fedora Atomic/UBL/bootc/Zirconium; package the RPM, reboot once if `getent passwd greeter` is empty, configure `/etc/greetd/config.toml`, enable `greetd`; `dms-greeter sync` *may* still work (`dankgreeter/installation.mdx` "Immutable and image-based systems"). RPM ships the sysusers/tmpfiles declarations needed for the `greeter` user on ostree.
8. **`settings.json` read-only** — migration/write-back won't persist until writable (`advanced-configuration.mdx:92`); home-manager-managed settings show "settings read-only" popup (`nixos-flake.mdx:309`).
9. **Auto-login caveats** — greetd `[initial_session]` auto-login is a physical-security reduction; first login always interactive because it needs remembered user+session (`dankgreeter/configuration.mdx` "Auto-login").
10. **PAM caution** — keep a root terminal while changing greetd/lock PAM; an invalid greetd stack can prevent graphical login (`dankgreeter/authentication.mdx` :::caution).
11. **Niri specifics** — screenshots need niri 25.11+; DMS window app-id is `com.danklinux.dms` (drop old `org.quickshell` rules); `DMS_DISABLE_LAYER`/layer envs fix stacking (`advanced-configuration.mdx`); notification/popout layer overrides.
12. **Dank Island** — a bar instance designated as Island is excluded from `bar` visibility commands (return `BAR_IS_ISLAND`; use `island` target) — `keybinds-ipc.mdx` (island/bar).
13. **Multi-user greeter** — only the main admin runs full `dms-greeter sync`; everyone else `sync --profile` (full sync from multiple users repoints root cache symlinks) — `dankgreeter/configuration.mdx`.
14. **DMS floating rule on by default** — Settings → Theme & Colors → Floating Windows → Open Windows Floating manages the niri window rule in `windowrules.kdl`; creates the fragment+include via a First Time Setup banner.
